## T8 Claude 显式缓存支持（2026-08-13 新增，参照 RikkaHub promptCacheTtl）

**背景**：DeepSeek/OpenAI/Gemini-implicit 等自动前缀缓存模型只需保前缀即可命中（T4 已覆盖）；但 Claude（Anthropic）与 Gemini/百炼 explicit 模式**必须客户端插 `cache_control` 标记**才缓存，Reasonix 当前不支持 → 用 Claude 时缓存永远 miss。

**目标**：客户端支持显式缓存断点（cache_control: ephemeral），维护稳定缓存前缀。

**参照**：RikkaHub Agents `ProviderSetting.promptCacheTtl`（ClaudePromptCacheTtl） + `ClaudeProvider.kt` 中 `put("cache_control", cacheControlEphemeral(...))`——仅设计参考（AGPL→MIT 只借鉴不搬码）。

**改动文件（预估）**：
- `data/api/ReasonixApi.kt` / `ReasonixSseClient.kt`：请求体支持 messages 中插入 `cache_control` 标记（Claude 兼容端点）；
- `data/AppSettingsStore.kt`：缓存开关 + TTL 档位（off / 5min / 1h）；
- `ui/viewmodel/ChatViewModel.kt`：按设置对稳定前缀（system + 工具描述 + 注入段落）标记缓存断点；
- `ui/screen/SettingsNetworkScreen.kt` 或新设置项：缓存配置 UI。

**验收标准**：
1. 连接 Claude 兼容端点时，请求体 system/前缀处出现 `cache_control: {"type":"ephemeral"}`；
2. usage 返回 cache_read/cache_creation token 可观测（统计条展示）；
3. 开关关闭时请求体不含 cache_control（行为与现在一致）；
4. 编译通过 + 自测（需 Claude 端点实测）。

**前置依赖**：T3 指纹门禁（需 androidx.biometric）之后做；本项涉及请求体结构变更，建议独立版本验证。

> **核实结论（2026-08-13）**：本项在 Reasonix 架构下**无客户端改动项**。
> 客户端只连自部署 serve（POST /submit `{"input":...}`，无 messages 结构）；serve 端
> internal/provider/anthropic/anthropic.go 已内置 cache_control 断点布置（非 deepseek 时：
> system 末块/tools 末块 + 最后消息末块打 `cache_control: ephemeral`，默认 5m TTL，≤2 断点），
> DeepSeek 上游忽略 cache_control 走自动前缀缓存（正是 T4 客户端保前缀能生效的原因）。
> 因此「客户端请求体插 cache_control」无从落地——断点布置属 serve 侧职责，已完成。
> 若未来 serve 需要 TTL 可配（5m/1h），改动应在 reasonix-server 而非本仓库。
